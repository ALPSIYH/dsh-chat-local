> 历史设计稿（2026-09-17），不是当前实现契约。现行行为见 [Agent 记忆架构](../../agent-memory-architecture.md)：C 是对象的房间运作计数；私人经历与判断归属于稳定 Agent 身份；reset 只重置插件投影，不清空原生上下文；评测始终仅作描述统计。本稿中的因果实验设想不表示这些识别条件已经实现。

## 0. 把目标说准

本插件要做的不是「记忆」一件事，而是三层，且三层的成败标准完全不同：

| 层 | 内容 | 判定标准 |
|---|---|---|
| L-A 事实记忆 | 跨对话可复用的知识、结论、口径 | 检索准确率 / 是否省掉重复交代 |
| L-B **关系印象** | 对「我与某个对手方之间发生过什么」的持久表征 | 是否可查询、可证伪、可追溯 |
| L-C **印象影响未来互动** | 印象反过来改变行为 | **因果主张**：需要对照臂与可指派变量 |

**与标准 GABM 的分界线**：常规 GABM 的交互是**一次性的**（每个 episode 或每个 run 从干净状态开始，agent 不带跨局状态）。我们要的是**跨 episode 携带状态**——这既是产品价值，也是研究方法论的转折点：一旦状态跨局携带，**"上一次发生了这件事"就变成下一次的自变量**，于是必须能被精确记录与重置。

**由此得出硬约束**：L-B 的载体必须是**第一类记录**（有时间戳、有证据链、有有效期、可被外部设置与清零），**不能是模型自由撰写的散文**。理由有三，都有实证：

1. **"recall is not compliance"**（Always-On 综述）：被召回的正确纠正仍会被违反。仅靠"把印象注进提示词"观测到的差异，可能只是措辞差异。
2. **失效模式有实证**：MAST 十四类失败里包含"对话历史丢失 / 对话重置 / 信息隐藏 / 忽略他方输入"；重复博弈中模型对"公开声明是否有约束力"理解不一致，payoff 差距**第 0 轮就出现并持续 10 轮**。
3. **因果推断需要可重置**：要回答"印象是否改变了未来互动"，必须有 **持久化臂 vs 每局重置臂**，且两臂初始条件匹配。模型自动改写的散文无法保证这一点。

## 1. 五个方案

「印象」到底放在哪、由谁形成、能不能被当作自变量 —— 这是真正的选型分歧。

| 方案 | 印象在哪 | 谁形成 | 可否作为实验自变量 | 可否被证据证伪 | 主要失效模式 |
|---|---|---|---|---|---|
| **A 显式关系状态**（模型产出 appraisal） | 结构化记录：`(observer, target, stance, confidence, evidence[])` | **模型**，经窄接口写入 | ✅ 可 | ✅ 有 evidence 链 | 抽取错误；模型可能写下无人要求的判断 |
| **B 纯情节检索**（无显式关系变量） | 只在过往回合的原文里 | **推理时的模型**，临场形成 | ❌ 无法直接干预 | ⚠️ 间接 | 检索质量决定一切；同一日志不同 agent 形成不同印象，因果分析变难 |
| **C 确定性派生声誉**（日志的纯函数） | 由台账/投递/验收等**算出来**的计数与比率 | **代码**，无模型参与 | ✅ 可（可设、可清零） | ✅ 完全可复算 | 只能捕捉 schema 能计数的东西，丢掉语气与语境 |
| **D 自我叙述笔记**（prose） | `DREAMS.md` 式的自由文本 | 模型，后台自主改写 | ⚠️ 弱 | ❌ 难 | 漂移、无界、可被投毒、不可审计（**研究场景下不应用作权威存储**） |
| **E 制度/规范层** | 章程、义务、约定 | 成员提案 + 全员批准 | ✅ 可 | ✅ 版本化 | **本插件已有**；但它是集体的，不表达二元信任 |

文献锚点：A 对应 Concordia 的 `perceived_role` / `SocialDeceptionGameLedger`（真值 `role` 与 `perceived_role` 并存，是仓库里唯一先例）与 AgentSociety 的有向带权边；B 对应 Generative Agents 的记忆流与 Hermes 的 `session_search`；C 对应 MAP-Graph 主张的"provenance 是运行时控制信号而非事后审计"；D 对应 OpenClaw 的 dreaming 与 Concordia 的人工撰写跨局策略；E 对应本插件章程与 Concordia `state_formation`。

## 2. 推荐：C 为骨架 + A 为覆盖层 + B 补细节，D 只做展示

**理由（按重要性）**：

1. **C 让印象成为可复算的第一类量。** 关系状态是日志的纯函数 → 任何时刻可重算、可对比、可清零。这是做实验的前提，而且**零模型成本、零抽取误差**。
2. **A 补 C 抓不到的东西。** C 只能数"验收被退回几次"，数不出"我认为他在关键处含糊其辞"。A 用模型写 appraisal，但**必须挂 `evidence_event_ids`**，否则不可证伪 —— 这正是 Always-On 综述的 provenance 轴。
3. **B 负责长尾语境。** 需要原始语气时才检索原文，不让它承担"关系状态"这个职责。
4. **D 只作为给人看的摘要，绝不作为权威存储。**

**一条必须同时做的设计（否则"印象影响互动"测不出来）**：光把印象注入提示词不算影响互动，必须有**行动层的钩子**。例如：

- 注入钩子：回合提示词里给「你与被征询者的关系摘要」（低信任 → 明确要求核验）。
- 行动钩子：**治理门**。设计初稿写的是「对**低信任对象**的高影响动作」，实现改为读**行动成员自己**那一对记录：一次工具执行不指名对手方，「对象」只能是行动者本人，规则因此读作「房间现在能不能可靠地让这个成员做这件事」（`lib/gate.js` 的 `evaluateGate`，行为见 README「行动治理门」一节）。判定为：高影响动作在「发给他的投递失败过、从未成功送达」时要求额外确认；可能是评审的动作（含映射表未登记的工具）在他名下还有未闭环分歧时要求独立验收。
- 只有注入钩子时，观测到的是措辞差异；加上行动钩子后，观测到的是**可测量的行为差异**（动作被拒次数、验收通过率、接手人选择分布）。

## 3. 一个近零成本的起点：你们已经有派生声誉的原料

台账、投递与验收里已存在**可确定性计算**的关系信号，不需要新采集、不需要模型：

| 已有信号 | 关系含义 |
|---|---|
| `deliveries[].status`（sent/delivered/failed/superseded）+ 重试次数 | 该成员是否按时接手、是否反复失败 |
| `acknowledgement` 延迟、`submission` 与 `review` 结果 | 认领与交付的可靠性 |
| `review.verdict`（approve / request_changes）次数与理由 | **公开**的质量评价（天然适合作为声誉来源） |
| `progress blocked` 的真实性（后续是否被解除、是否只是缺材料） | 是否把材料问题误报为权限问题 |
| 未闭环前置导致的停滞、`triage` 处置、`dispute` 未解决计数 | 协作摩擦史 |
| 章程提案被异议 / 被 `superseded` | 规则制定上的可信度 |

也就是说：**L-B 的第一版可以完全建在今天的台账上**，先出 C 层，不需要等事件日志。但要走向"可证伪 + 可反事实"，就必须有日志（见 §5）。

## 4. 推荐 schema（C 层 + A 层）

沿用调研里的 `event` / `appraisal` 分离；C 层由事件确定性派生，A 层由模型写入但必须带证据。

```
# C 层：由事件确定性派生的二元关系状态（可重算、可清零）
relationship_snapshot(observer_id, target_id, as_of,
      handoff_accept_latency_ms, delivery_success_rate, delivery_failures,
      reviews_approved, reviews_changes_requested,
      blocked_reports, blocked_confirmed, stalled_predecessors,
      unresolved_disagreements, charter_proposals_superseded,
      derived_from_event_ids[])          # 只追加快照，不覆盖历史

# A 层：模型的评价（可选覆盖层，必须可证伪）
appraisal(id, event_id, observer_id, about_agent_id, at,
      stance ∈ {trust, distrust, neutral}, confidence ∈ [0,1],
      claim, perceived_role, evidence_event_ids[],
      valid_from, valid_to)              # 撤销而非删除

# 治理门：印象影响行动的地方（可记录、可审计）
action_gate(id, at, actor_id, tool, judgement, risk_class, action,
      basis{observer, target, as_of_tick, version, derived_from_count, counters})
      # 初稿这里是 target_id / action_type / decision / basis_snapshot_id /
      # applied_by，实现改成了上面这一行：actor_id 就是被判定的行动成员，
      # observer == target == actor_id；只在判定为拒绝时追加（allow 不写事件）；
      # 没有 applied_by —— 门一律由房间策略作出，不存在「模型决定的门」。
```

设计要点：
- **`relationship_snapshot` 只追加**：印象随时间的历史本身是研究对象（"信任何时转折"）。
- **`appraisal` 带 `valid_from/valid_to`**：撤销而非删除（TEPA：按键撤销 0.950 vs append-only/LWW 0.210 < 无记忆 0.309）。
- **门的作者身份。** 初稿用 `action_gate.applied_by` 区分「策略决定」与「模型决定」。实现里没有这个字段：治理门一律由房间策略作出，判定只读房间自己记录下来的计数器快照，模型没有声明一个门的入口（实验干预/manifest 端点上的 `appliedBy: "human"` 是另一件事，与门无关），所以这一维不存在需要归因的歧义。
- **印象的键**：先定"什么是同一件事"（对手方 × 能力维度？还是单一标量？）。TEPA 的教训是**键的设计比失效策略更早决定成败**。

## 5. 与 P1（事件日志）的关系

| 层 | 能否今天建在现有 `rooms.json` 上 | 是否依赖事件日志 |
|---|---|---|
| C 层（确定性声誉） | ✅ 能，原料已在台账里 | 做"快照与重算"够用；做"证伪与反事实"需要日志 |
| A 层（模型 appraisal） | ⚠️ 勉强，但没有日志就无法回头验证它当时基于什么 | **强依赖** |
| 治理门（行动钩子） | ✅ 能（在工具守卫里加判定并记录） | 建议同时落日志 |
| L-C 因果实验（持久化 vs 重置臂） | ❌ 不能 | **必须**有日志 + snapshot/restore + 干预 API |

即：**产品价值可以先上 C 层 + 治理门；研究价值必须等 P1。** 这也是上一份调研里"P1 先做"的结论在这个具体目标上的投影。

## 6. 实验设计含义（若将来要发表）

- 两臂：**关系状态跨局持久化** vs **每 episode 重置**，初始条件匹配（同一 run manifest、同一初始人格、同一种子策略）。
- 自变量必须落盘：每回合的印象快照 + 注入块 + 行动网关判定。
- 因变量建议取**行为量**而非措辞量：接手人选择分布、验收退回率、动作被拒次数、争议未解决时长。
- 单模型不构成群体：至少两个模型家族/版本，以 run/seed 为分析单位，预先指定独立运行次数，报方差。
- 主张定级：只做**探索性/机制性**，明确声明不做预测。

## 7. 已定的设计默认（原开放问题 → 决策）

选型已定：**C 骨架 + A 覆盖层 + 治理门**。以下五项按「研究可用性优先」给出默认值；要改时改的是参数，不是架构。

| # | 原问题 | 决定 | 理由 |
|---|---|---|---|
| 1 | 印象私有还是公开 | **对 Agent 侧私有**。`review.verdict` 这类**本来就已经是公开动作**的进入共享声誉；其余 appraisal 只进入观察者本人的那一行——`chat_relationships` 只返回调用者自己的一行，成员看不到别人的判断。房间主人的只读端点 `GET /rooms/:id/appraisals` 返回**完整矩阵**，它与插件其它端点一样挂在本地回环、不认证调用者（README 已披露），所以「私有」是相对于 Agent 工具而言，不是对任何能访问回环的本地进程保密 | AgentLeak：agent 间消息泄漏 **68.8%** vs 最终输出 27.2%，只看输出的审计漏掉 **41.7%**；MAP-Graph：摘要会掩盖 private/poisoned/revoked 来源。且插件语义上 review 本就是公开动作 |
| 2 | 关系粒度 | **二元 `(observer, target)` 为准**；群体印象只作为 C 层的**聚合视图**，不单独存模型 appraisal | Concordia 只有二元先例；群体 appraisal 无法归因到具体证据 |
| 3 | 印象是否影响调度 | **第一版不影响。** 印象只经治理门影响"动作是否被允许 / 需额外确认 / 需独立验收" | 回合顺序是目前**唯一已经做对**的可复现性要素（按成员配置序、单轮不并发）。动它就要额外记录并重做验证 —— 单独开一个决策 |
| 4 | 人类可否设置/清零 | **必须可。** 显式 API + 审计记录 `appliedBy: "human"`（事件里写在 `payload.appliedBy`） | 研究需要"每局重置臂"；不可重置就无法做反事实 |
| 5 | 探索配额 | **未实现，也尚未决定。** 建议的「加最小版本」（低信任目标仍按配额获得任务，配额与探索记录落盘、可关闭）没有落进任何一处代码：当前实现没有配额、没有探索记录，也没有对应的事件或配置项 | 提议的理由仍是待解的取舍（低信任者永远拿不到任务 → 永远无法改善）；在实现之前，本文不把它当作已决定的行为 |

**仍属真正取舍的**：#3 标记为「第一版默认、需要时单独决策」；#5 尚未实现，也尚未决定。其余三项是架构级承诺，改动等于换方案。
