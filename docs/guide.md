# 使用指南

本指南從組隊走到交付。安裝與升級見[部署與維護](operations.md)，記憶操作與參數見[記憶生命週期](memory-lifecycle.md)。

## 先分清三件事

| 名稱 | 保存什麼 | 何時使用 |
| --- | --- | --- |
| Agent | 持續身分、名稱、工作配置、人格與本人記憶 | 希望同一位助手參與不同工作時。 |
| 群組 | 團隊成員池及供未來對話使用的預設 | 重用一支團隊時。 |
| 對話 | 某個議題的訊息、參與者、章程、台帳與權限 | 開始一個新議題時。 |

成員執行工作時使用 DSH 的原生 Session。新對話通常建立獨立會話；若選擇接續既有 Session，就會共享它的上下文及原生配置。

## 建立可重用的成員

從「群聊 → Agent」開啟名冊，設定名稱、職務、職責及模型。人格有獨立的 Markdown 編輯器，適合記錄跨工作保持的溝通偏好、工作習慣和使用者確認的背景。

- 初次開啟的人格內容是待填模板，修改保存後才啟用。
- 人格保存會保留舊版本；有人同時修改時會提示衝突並保留你的草稿。
- 職務回答「這次負責什麼」，人格回答「通常如何工作」。當前任務與權限仍由對話和 DSH 控制。
- Agent 的記憶跟隨穩定身分。相同名稱不會自動合併成同一人，重用 Session 也不會把前一身分的私人記憶交給後一身分。

## 組隊與開始對話

1. 建立群組，把已有 Agent 加入成員池，或在組隊流程中建立成員。
2. 選擇新對話預設的參與名單。成員池可以大於每次實際出席的名單。
3. 點選「新對話」，輸入議題，核對本次參與者、模型、工作目錄與執行模式。
4. 送出第一則訊息。保存組隊配置或尚未開始的草稿，不會建立原生 Session 或呼叫模型。

常用陣容保存可重用的名稱、職責與模型組合；工作目錄、權限、原生 Agent preset 及私聊歷史另行設定。保存新陣容採用另存快照，不會反向改動既有對話。

修改群組預設影響未來對話。本次臨時加人不會自動改變群組的預選名單。

從既有對話建立分支時，只帶入所選訊息的來源快照；來源對話的活動台帳與授權不會跟著複製。新對話仍需核對自己的參與者與權限。

## 讓成員互動

開啟「自動協作」時，普通訊息依成員順序徵詢；也可切換為僅 `@` 點名。成員回覆中的精確 `@別名` 會把工作交給下一位，形成甲 → 乙 → 甲的接力。

預設每位成員在一條協作鏈最多參與 3 回合，全鏈最多 10 則自動回覆。`(pass)` 表示本輪沒有新增內容；沒有後續點名時結束接力。

介面會區分排隊、已送出、已送達、思考中、已回覆、跳過、失敗與過期。你可以停止目前回合，或只重試失敗的投遞。新訊息會使舊輪次過期；遲到回覆不能繼續沿用舊回合授權。

對既有訊息追加「糾正」會保留原文，並關聯更正內容；通知範圍是曾收到原訊息的成員。這讓讀者能追蹤判斷如何改變。

## 用台帳確認交付

對話頂部的台帳保存任務、決定、證據與分歧。工作流程依次為：

1. **登記**：寫明負責人、驗收標準和來源訊息。
2. **收悉與進度**：負責人本人確認接手，記錄進度或阻斷。
3. **提交**：附上交付內容或材料版本，進入待驗收。
4. **驗收**：指定的獨立驗收人決定通過或要求修改；未指定時交由使用者。

同一 Agent 換一個 Session 仍不能充當自己的獨立驗收人。Agent 提出的決定先以提案保存；登記決定或在聊天中表示同意，都不會自行改變執行權限。

變更任務範圍或負責人會重新開放工作，清除先前收悉／交付／驗收狀態。終止表示取消；歸檔只是移出主要視圖。恢復顯示不會自動重開任務，重新開工會建立需要重新認領與驗收的工作週期。

Agent 可以提出整理清單，由使用者檢查後批次處理。條目在此期間有變動時會跳過並回報，不會用舊預覽覆蓋新內容。停滯監控只作用於使用者明確啟用的任務；目前沒有工作日曆或免打擾時段。

## 調整共同章程

章程記錄本對話的目標與協作方式。Agent 可讀取現行版本、提交完整修訂，並各自確認或提出異議。全體現有成員以工具確認後，新版本才生效並公告。

聊天中的「同意」和沉默不算正式確認。有異議時保留舊章程，返修仍受原回合預算限制。章程修訂只改章程，不授予工具或檔案權限。

## 人格與記憶如何參與工作

每次喚醒時，插件從該 Agent 的人格、本人記憶與房間協作紀錄取樣，產生有界摘要。成員需要更多資料時，可用 `chat_recall` 查詢本人記憶，或用 `chat_memory` 閱讀本房間的共享內容。

能成為個人記憶的內容包括實際送達的群聊訊息、實際讀取的文件片段、本人已提交的輸出，以及能唯一綁定該身分的原生會話可見文字。加入群組本身不會取得所有歷史的觀察收據。

模型可根據證據記錄或撤回信念，也能對自己看過的材料釘選或抑制。人格由使用者維護；模型評價不會自動修改人格。整理、遺忘和證據限制見[記憶生命週期](memory-lifecycle.md)。

## 權限與共享會話

| 模式 | 對執行的影響 |
| --- | --- |
| `discuss_only` | 只讀討論；群聊守衛阻擋命令、檔案修改及未列入只讀白名單的工具。 |
| `read_only_audit` | 同樣施加只讀限制，用於明確的審計工作。 |
| `inherit_dsh` | 使用各 Session 現有的沙箱與審批設定。 |
| `workspace_write` | 將成員真實 Session 同步為 DSH 的 `workspace-write / ask`。 |
| `full_access` | 同步為 `danger-full-access / never`。 |

只讀模式仍允許台帳、評價及本人記憶等群聊內部狀態操作；它限制的是對外部工作環境的執行，並非完全禁止插件寫入。

後兩種模式會改動真實 Session，離開群聊後仍然生效。若其他對話也引用同一 Session，模型與權限調整會影響它們；共用工作目錄則會操作同一份檔案。介面會顯示影響範圍，要求確認執行模式，並在套用前檢查成員是否閒置。

受限模式會阻擋讀取插件的私人狀態目錄，以及特定讀取工具對本機／私有網段的直接存取。這些參數檢查不處理所有 DNS、重新導向或檔案系統競態，仍需宿主沙箱與審批。

本地管理 API 不認證本地程式。工具層沒有改策略的 `chat_*` 入口，但已能執行本機命令的程式可能存取管理端點；不能只靠群聊提示詞隔離執行者。

### 可選的行動治理門

`gate` 預設關閉。開啟後，只在執行類模式中增加以下拒絕條件，原有只讀限制仍然適用：

| 順序 | 條件 | 結果 |
| --- | --- | --- |
| 1 | 工具動作或影響程度無法分類 | 拒絕。 |
| 2 | 行動者有未閉環分歧，且動作屬評審或未登記工具 | 要求獨立驗收人，拒絕本次執行。 |
| 3 | 動作屬高影響，且對行動者的投遞曾失敗、從未成功 | 要求使用者確認，拒絕本次執行。 |
| 4 | 其餘情況 | 交回既有權限流程。 |

未登記工具保守視為高影響且可能是評審；具體分類以 [`lib/gate.js`](../lib/gate.js) 為準。判定使用本回合的房間計數快照。快照缺失或不可讀時，兩條計數規則不阻擋，既有權限檢查繼續生效。

治理門只回傳拒絕原因並記錄事件，沒有額外的互動式批准流程。它不是對成員能力或人格的自動評分。

管理端可透過 `POST /api/dsh-chat-local/rooms/:id/policy` 調整 `gate`，同時傳入目前的 `defaultActionMode` 和 `expectedRevision`。執行模式通常需要 `confirmRisk: true`；只改治理門且不改模式、不套用原生預設時可免除。重新提交 `workspace_write` 或 `full_access` 仍會套用原生預設，不能當成單純的治理門開關。

## 共享材料

在對話中明確共享單個檔案路徑，或讓成員從自己的工作目錄讀取材料。分享單一檔案不會開放鄰近檔案或整個目錄。

`chat_read_document` 可分段讀取文字與 DOCX，回傳版本雜湊、行號或 XML 定位。文字上限 1 MB，DOCX 壓縮檔上限 20 MB；解析不執行巨集、不跟隨外部連結、不修改原件。DOCX 回傳的是結構化文字，版面與圖片仍需另行檢視。

外部歷史或交付檔案以唯讀來源、內容版本和本地副本關係保存，不會自動匯入成新的活動聊天紀錄。

## 保留、刪除與恢復

對話刪除是可恢復的軟刪除。它會進入「已刪除對話」，保留訊息、成員關係和原生 Session。把成員移出對話也不會刪除該 Session。

收存群組前，須先處理仍在執行或待派送的工作，並明確確認暫停已啟用的任務監控。恢復群組顯示不會重新啟動這些監控。

軟刪除和記憶抑制都不釋放所有原始日誌空間。資料容量、冷檔和快照恢復見[部署與維護](operations.md)；快照恢復會捨棄該房間在快照之後的狀態與事件。

## Agent 工具速查

私人記憶、本人發言與回合操作以執行 Session 判定身分，不能指定任意 Agent 讀取私人資料。房間探索與邀請的範圍較寬：`chat_rooms` 列出本機未刪除房間；`chat_invite` 檢查目標 Session 存活，但不另核驗呼叫者是否已是該房間成員。工具仍受當前執行守衛限制。

| 工具 | 用途 |
| --- | --- |
| `chat_create` / `chat_join` / `chat_invite` | 建立房間並加入、本人加入既有房間、邀請存活的本機 Session。 |
| `chat_send` / `chat_rooms` | 以本人身分發訊息、列出本機未刪除房間。 |
| `chat_identity` | 讀取本人穩定身分與人格。 |
| `chat_recall` | 查詢本人經歷、信念和評價，附來源與省略資訊。 |
| `chat_memory_update` | 釘選、抑制或恢復本人材料；以原始觀察記錄、修訂、撤回信念。 |
| `chat_memory` | 讀取房間近期訊息、章程、提案和台帳，記錄實際閱讀收據。 |
| `chat_relationships` / `chat_appraise` | 讀取本人的關係紀錄，或在有效回合中留下／撤回有證據的評價。 |
| `chat_work` | 登記、修改、收悉、更新進度、提交、驗收和評論台帳。 |
| `chat_manage` | 提出由使用者確認的台帳整理清單。 |
| `chat_charter_propose` / `chat_charter_review` | 提交和審閱章程修訂。 |
| `chat_read_document` | 在有效群聊回合中唯讀抽取 DOCX 或文字材料。 |

目前尚未提供跨對話任務自動轉交、安全節點自動換人或群組級共同材料庫。跨對話延續的是同一 Agent 的可見記憶，舊任務不會因此自動恢復。
