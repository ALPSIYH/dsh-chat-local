# dsh-chat-local

**中文** · [English](README.en.md)

讓多個 Agent 在 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 裡討論、分工與交付，並各自保留持續的身分、人格設定和親歷記憶。

你可以組成一支團隊，為不同議題開新對話，讓成員互相點名、提交成果、要求驗收。同一位 Agent 換了對話或執行會話，仍可查詢自己真正看過的材料；其他成員的私人經歷不會因此變成共同記憶。

## 能做什麼

| 功能 | 實際用途 |
| --- | --- |
| 團隊與對話 | 重用成員和預設配置，每個議題保留獨立的訊息、工作台帳與權限。 |
| Agent 互動 | 依序徵詢成員，或用 `@` 指定對象；成員也能接力回覆，輪次有上限。 |
| 工作台帳 | 記錄負責人、證據、進度與交付；由指定驗收人確認結果。 |
| 人格 Markdown | 為每位 Agent 設定性格、溝通偏好與工作習慣，保存版本並處理編輯衝突。 |
| 個人長期記憶 | 從實際送達、讀取與本人輸出建立記憶，查詢時保留來源。 |
| 記憶整理 | 自動合併重複材料、降低舊材料的預設召回優先度，支援釘選與可逆抑制。 |
| 執行與權限 | 成員透過真實 DSH Session 工作，沿用宿主的模型、工具、沙箱與審批。 |

## 開始使用

### 1. 安裝

已驗證的 DSH 版本是 `0.1.7-rc.2`，載入範圍限定為 `>=0.1.7-rc.2 <0.1.8-0`。需要先安裝 [dsh-bridge](https://github.com/baixianger/dsh-bridge)，由它負責本機會話喚醒與投遞。

```sh
dsh plugin --profile web add github:ALPSIYH/dsh-chat-local
```

安裝後重啟 `dsh web`，點選側欄的「群聊」。既有安裝升級前，先依[升級與備份](docs/operations.md)保留完整資料目錄。

### 2. 設定 Agent

在「群聊 → Agent」建立或編輯成員。名稱、職務與模型屬於工作配置；「編輯 … 的人格」則描述這位 Agent 跨工作保持的偏好。

人格欄位最初是**未啟用的待填模板**。例如，你可以寫：

```md
## 工作習慣
先提出一條可驗證的路徑，說明關鍵假設，再開始實作。
收到新證據時修正判斷，並說清楚哪個前提變了。

## 溝通偏好
先給結論，區分已確認、推測和仍需查證的內容。
```

保存後的設定用於後續回合。人格不會自動改寫，也不會提高執行權限。

### 3. 建群組、開對話

建立群組並選擇成員，再為一個議題開新對話。你可以沿用團隊預設，也可以只調整這次的參與者、工作目錄與權限。

普通訊息在「自動協作」模式下依序徵詢成員；`@名稱` 可以定向交接。頂部台帳用來追蹤負責人、提交內容與驗收。單純保存成員或團隊配置不會啟動模型。

完整操作見[使用指南](docs/guide.md)。

## Agent 如何延續記憶

```text
持續的 Agent 身分
├── 人格：使用者維護的 PERSONA.md
├── 經歷：本人確實收到、讀取或產生的內容
├── 信念：本人根據證據提出、可修訂的解釋
└── 評價：本人對其他 Agent 的有來源判斷
```

群聊投遞提供有長度上限的記憶摘要，Agent 也能用 `chat_recall` 查詢更多。原生會話的自動注入另受 DSH 預設控制：`minimal` 會停用執行期上下文，因此不自動帶入人格與個人記憶。參與者面板會顯示最近一次提示組裝所觀察到的狀態；要啟用，請開啟原生會話並選擇支援執行期上下文的預設。房間中的發言、投遞和驗收計數另外保存，供回顧協作過程使用。

目前的自動整理是**保留原文與來源的去重**；「遺忘」是可逆的召回衰減或抑制，原始日誌仍保留。尚未提供模型語義歸納、自動人格演化，也未證明真實模型能長期維持穩定人格。詳見[記憶生命週期](docs/memory-lifecycle.md)。

## 使用前需要知道

- **權限會影響真實 Session。** 工作區寫入、完全權限等設定在離開群聊後仍可能生效。共用工作目錄也代表操作同一份檔案。詳見[權限與共享會話](docs/guide.md#權限與共享會話)。
- **資料保存在本機。** 預設目錄為 `~/.dsh/dsh-chat-local/`；目前狀態格式是 v17。回退至不相容的舊版時，需同時還原該版資料。
- **記憶有可見性與容量邊界。** 未收到的材料、掛載前的原生歷史和非文字內容，不會自動變成記憶。容量不足時拒絕新寫入，沒有無限歷史保證。
- **本機管理介面不做呼叫者認證。** Agent 工具的私人記憶隔離不等於對有本機檔案或管理 API 存取權的程式保密；日誌與人格檔未加密。
- **可追溯不代表內容正確。** 日誌能核對來源與修改痕跡，模型仍可能推理錯誤。測試通過或短期回覆一致，都不足以證明已完整模擬一個人。

## 開發

```sh
npm ci
npm run check
```

修改共享文字／工作協議後先跑 `npm run build`；`check` 會檢查生成內容、語法和回歸測試。測試原生 DSH 整合時，需設定 `DSH_MODULES_DIR` 指向 DSH 安裝中的 `node_modules`。具體入口見[維護指引](CONTEXT.md)。

離線日誌校驗入口是 `scripts/verify-event-log.mjs`；請按[部署與維護](docs/operations.md)使用停寫後的資料副本。
