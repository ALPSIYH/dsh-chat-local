# dsh-chat-local

面向 DeepSeek Harness 0.1.5-rc.2 的本地多 Agent 群聊插件。群组复用成员和模型偏好，每段对话使用独立的真实 DSH Session；原生会话历史不克隆，执行、权限和模型目录仍由 DSH 管理。

## 当前行为

- v0.16.1 适配 DSH 0.1.5 的槽位重构：工作区改注册到 `shell.overlay` 覆盖层（DSH 0.1.5 移除了旧的 `conversation` 槽，主区域改为 `main` 键控面板），并移除对旧 `AppFrame` 栅格的手工改造。进入群聊不再隐藏原生侧栏，返回 DSH 不会残留样式。

- v0.16.0 分開 Agent 名冊、群組成員池、新對話預選與本次參與者。新群組從空白開始，可混合已有與新建 Agent；純保存不建立原生 Session，不執行模型。臨時對話不需先建群組。話題先寫內容，稱呼／職務／模型皆可在指定作用域調整。原生模型目錄與資料夾選擇器共用；進階接續原生歷史需預覽忙碌、共享範圍與權限影響。名冊收存不刪歷史引用；群組收存檢查活動工作並明確暫停監測，恢復不自動開工。資料升至 v14，舊資料、兩份未完成草稿與 Session 綁定以追加識別方式保留。
- 本版新建入口每次開空白頁，輸入後才保存草稿；可從分開的群組／對話草稿入口繼續。設定變更、未知結果與版本衝突均保留輸入及原操作憑據。下列 v0.15／v0.14 描述是歷史行為，與本版不同時以本段為準。
- v0.15.0 改为持久化草稿与本次阵容：直接写主题、选择／增减成员并从 DSH 模型目录配置，不先建立原生 Session；可保存多套常用阵容，环境与权限不随阵容迁移。群组可以为空，保存群组不创建同名对话。首发使用持久化凭据，恢复时不会盲目重播未知执行。Agent 的 chat_manage 可提出固定清单，用户一次确认归档、终止或取消指定过时依赖；保留验收语义与完整历史。执行失败须核对结果后按当前权限接续。数据升级到 v13，不能直接用旧程序读取；升级前备份。跨对话任务转交、运行中自动换人、群组级共享材料未包含在本版。
- v0.14.0 加入“群组 → 多个独立对话”：主入口为新对话，新建群组可复用当前团队。首条用户消息生成可编辑主题。新对话不继承旧消息、台账、活动队列、材料授权或验收结论，不取消后台其他对话。未操作的原房间完整迁移为一个对话，保持原 ID 和 Session 绑定。
- 分支讨论先显示选定消息供确认，可加背景；新对话保留来源快照与返回入口，不把来源当成新指令或授权。当前界面从单条消息分支，不自动挑选、汇总整段历史。
- 新对话预留独立 Session ID，首次发言或配置时按需准备。冻结成员配置包含名称、职务、职责、工作目录与准确模型/推理等级；不调用模型生成。初始新对话为只读审计；可明确将完全权限等当前策略保存为群组默认，供未来对话使用。准备新的原生会话时同步实际预设，跟随 DSH 模式除外。
- 独立原生会话的成员、模型和章程修改只影响当前对话；“设为群组默认”显式保存当前已提交配置，已有对话不变。若连接的是已存在或被其他对话引用的原生 Session，模型更改会显示共享影响并要求确认，其他引用对话运行中不能修改。群聊模型选择通过 DSH 原生提交原语，不触碰 DSH 全局默认模型。此兼容 Adapter 针对 0.1.5-rc.2，原语缺失时拒绝准备或选择，不静默替换模型。
- 新对话与新群组创建使用持久化操作编号；同一操作的丢失响应和重启重试复用创建凭据。未开始的新对话默认返回已有草稿，明确“另开一份草稿”才增加；不同窗口有修订冲突时保留输入并要求选择，不覆盖新版本。侧栏只列当前群组的对话，空群组也可切换，已删除对话集中保留恢复入口。上下文隔离不等于磁盘隔离：相同工作目录仍指向同一份文件。

- v0.13.0 修复审计复现的 6 项可靠性问题：权限锁只跟随实际执行回合，跨房间排队不再覆盖；并发新消息以不可变回合代次调度；保存失败的同 ID 重试补做持久化并至多启动一次；重启核对所有残留处理中投递；迟到响应不再覆盖其他房间；纠正消息在响应丢失后复用操作 ID。失效的排队消息晚到时停止执行，同一原生回合混入多个群聊投递时不发布无法归属的结果。不会自动重跑历史任务或伪造完成。
- v0.13.0 将台账处理入口前移，折叠长交付与系统台账通知，分别统计待推进任务和证据；继续操作先准备收件人与任务草稿，新回合保存逐人次数和回复预算。未加载成员的权限通过 DSH 原生只读投影读取，未知/不匹配明确提示，不自动提权。文件列表支持全部文件搜索，Markdown 默认安全阅读并可切换源码；覆盖式检查器加入对话框语义、背景隔离与焦点恢复。GET 使用 ETag 条件同步和有界客户端缓存，不变响应不重复传输全文。
- v0.12.2 修复短文件名未关联已共享完整路径的问题：预览与 `chat_read_document` 共用解析器，只在精确文件名唯一匹配时只读打开；工作区或已共享路径存在同名文件时要求选择完整路径，不猜版本、不递归搜索目录。已知但缺失的同名文件也保留在选择中，避免静默改读另一份。错误区分未找到、名称未匹配、未共享、非普通文件与本机读取失败；继续保留单文件共享、房间隔离和版本哈希校验。
- v0.12.1 在事项卡片与阻断页提供“忽略旧阻断”和“移除事项”，说明可留空。忽略由用户判断，不要求条件检查通过：清除当前阻断/旧进展，任务回到待处理，不标记完成或自动启动；未有新工作变化前可撤销忽略。移除采用可恢复归档，从“已归档 / 已移除”恢复为待处理（决定为待决定），不复活旧验收。原报告和每次处理都保留审计历史。
- 忽略/移除取消该事项未发出的接手通知及停滞提醒，不中断已经运行的会话，不修改权限或关闭关联任务。恢复时不会重放旧通知。重复确认使用同一操作编号，新进展出现后旧撤销不覆盖新状态。Agent 被明确要求不因旧聊天重建用户已忽略/移除的问题；新实际失败仍可报告。
- 已提交或验收后，早于本次交付/验收的进展报告折叠为历史，不把旧权限报错继续呈现为“最近报告”；当前仍 blocked 的真实报告保留可见。
- v0.12.0 将协作台账的“受阻”补齐为条件检查与接手链路：读出当前负责人可访问的材料及哈希、检查已登记的前置事项，提供单文件只读共享、真实通知重试及文件查看后的返回入口。检查本身不登记文件、不改状态、不唤醒 Agent；文件可读不代表任务已恢复或内容版本正确。
- Agent 报告 blocked 时可附结构化 `blocker`（类型、具体原因、下一步、所需绝对文件路径、实际前置事项）。拒绝跨房间、自引用和循环前置依赖；归档不视为前置事项已经完成。旧阻断不被自动重写，显示原报告日期，并按当前条件复查。再次 acknowledge 不能解除阻断，须实测后 progress 或 submit。
- 接手通知持久保存，区分排队、发送、等回报、已回报、未回报、失败和中断。用户采纳决定时可将通知排到当前讨论结束之后，不再丢弃；新任务、待验收任务和已采纳决定也有接手/后续入口。重复请求沿用操作编号，不重复发送；只通知指定接手人，不解析任务标题中的额外 @。
- 重启或用户停止协作时，未完成接手通知转为明确中断，不自动重放；任务状态不因通知变为已解决。本轮结束却未回报时仍提示处理，不假装在运行。直接从台账发出的用户接手操作带可追溯来源，成员可据此报告进展，不要求用户先补发一条聊天。
- 受阻任务纳入“待我处理”；已排队等待回报时有独立反馈。台账可按事项、负责人和阻断文本查找；关联事项改为最多 8 项多选，不再因选择一项而丢掉其他关联。长任务说明/报告折叠，明确显示报告日期。已保存但刷新失败会明确提示，不误报保存失败。
- v0.11.1 将 DOCX 默认预览改为结构化阅读：标题、段落、直接设置的粗体/斜体、表格及合并单元格分别呈现。支持正文/脚注/尾注/批注切换、标题跳转、文内查找及清除、字号和展开阅读；脚注标记可跳到对应注释，并返回原引用段落。技术限制默认折叠，不再把 XML 定位码混入每一段正文。
- DOCX 的“显示段落定位”和“定位原文”保留审计入口；可复制段落、定位和文件 SHA-256。阅读结构仅用于文件预览响应，`chat_read_document` 仍返回原有带定位码的分段文本，不向 Agent 附带整份阅读结构，也不改变原文件。
- v0.11.0 加入安全的常用 Markdown 呈现、长消息展开、原文复制和房间导出。Markdown 导出包含完整对话与当前台账；JSON 包含完整房间快照及审计历史，并附 SHA-256 校验。不会额外读取成员私聊或引用文件。
- 发送以服务端保存确认作为成功依据，不再因为后续刷新失败而恢复草稿。响应丢失时保留发送编号与收件人，重试复用编号；同编号不同内容被拒绝，不覆盖发送期间新写的草稿。
- 取消旧版 2000 条消息的静默截断。界面仍只加载最近 200 条，旧消息通过全文搜索定位；不会恢复旧版已经删除的历史。
- 重启后把未完成的回合明确标为中断，把未完成投递标为可重试失败；不假装任务正在运行，也不自行重新执行。达到回复/成员轮次上限或投递失败时，显示原因及“准备继续”“核对未闭环事项”等入口。
- 文件路径与 @ 识别使用前后端共享协议；支持含空格的 Mac 路径，排除邮箱、代码和长英文名的误触发。切换房间时，迟到的搜索、历史和预览响应不覆盖当前房间。
- 新增权限详情入口，可查看五种模式并重新应用当前原生预设；沿用风险确认，不自动授予权限。窄屏收件人可换行、弹窗支持键盘焦点循环，页面隐藏时暂停轮询，同一轮询不重叠请求。
- v0.10.0 加入实际权限选择：只读讨论/审计、跟随 DSH、工作区内修改、完全权限。后两项调用 DSH 原生权限预设设置现有成员的真实 Session，不是只改台账或提示词。完全权限须明确勾选影响提示；应用后不自动启动任务。
- DOCX/文本可通过 `chat_read_document` 分段只读抽取，包含版本哈希和定位信息。除参与者工作目录外，用户在群里明确共享的单个文件也可读取，不开放其邻近文件或整个目录。
- 受阻事项提供处理入口：打开共享文件、跳转关联待决问题、调整实际权限、准备负责人重试消息、进入负责人原生 DSH 会话。不会仅靠换权限就伪造“已解除阻断”。
- 待决问题支持明确问题、2–4 个选项和各项影响；说明可留空。确认可通知提议者及关联负责人继续，但不打断运行中的协作。旧提议不伪造备选方案，支持请成员补齐或直接编辑。
- v0.9.0 补齐协作状态维护：Agent 可自行登记任务、待决定事项、证据与分歧；任务负责人本人收悉后报告进展/阻断、提交带材料版本的结果，再由指定的独立成员或用户验收。不再依赖用户逐条把聊天抄入台账。
- 成员每次唤醒都看到本人未闭环事项；分派、提交、退回在原协作轮的预算内精确唤醒接手人。不会另起无限后台工作，也不会自动开启监控。
- 台账支持待我处理、未闭环、受阻、待验收、分类和含归档筛选。任务与决定显示真实阶段；历史展示前后快照、操作者、说明、讨论来源，支持恢复为新版本。旧 done 记录没有验收元数据时不伪造验收。
- v0.8.0 加入章程自更新：Agent 可读取共享记忆、基于讨论消息提交章程提案、明确确认或提出异议。提交者与其余成员全部确认后自动生效，无需用户手动抄录；异议保留旧章程，并在轮次预算内返回提案人处理。普通回复中的“同意”不是工具确认。
- 章程检查器显示提案前后差异、讨论依据快照、逐人成员意见、待处理/已结束修订和生效版本。用户可搁置提案或将历史内容恢复为新版本；历史不删除。梳理章程/继续审阅按钮只准备消息草稿，不会覆盖已有草稿或直接唤醒模型。
- v0.7.1 优化呈现：沿用 DSH 的主题颜色与正文字号，统一线性图标、表单、头像和消息层级。桌面房间栏默认展开；680px 以下改为按需展开的房间抽屉；1120px 以下详情使用遮罩抽屉，更宽时与对话并排。
- 消息按日期分组；“回应”可跳转并短暂高亮原消息。输入框随内容增高，消息辅助操作在悬停/聚焦时显示（触屏常显）。背景同步错误在重连成功后自动清除，操作错误可以关闭。

- 从 DSH 侧栏底部进入群聊工作区。插件动态占用 DSH 原生 `conversation` 单槽；进入时只隐藏 DSH 导航与详情栏，群聊房间栏默认显示且可独立收放；“返回 DSH”一步恢复进入前的 DSH 布局。
- 可输入名称创建真实 DSH Session，也可搜索并加入已有 Session。
- 每个参与者都直接接入 DSH 的模型目录，可按供应商和模型名称选择，并可调整模型支持的推理强度；不输入、不猜测模型 ID。
- 人类消息先原子写入本地房间记录，再通过 `dsh-bridge` 投递。
- 新建房间默认启用自动协作；普通人类消息会按参与者顺序征询，单轮内不会并发争抢同一上下文。也可在顶栏切换为仅 @定向协作。
- 房间可持久保存目标、协作章程、外部记录来源，以及每位参与者的职责和交付边界；这些内容会在每次群聊唤醒时注入对应 Session，不依赖最近 24 条消息才能记住分工。
- “设置”检查器可修改房间名称、目标与章程；采用房间 revision 乐观并发检查，避免旧页面覆盖新配置。
- 参与者检查器可编辑群聊名称、职务与职责边界，并调整自动协作顺序。群聊名称就是精确 `@名称`，保存时会尝试同步真实 DSH Session 标题。
- 顶栏“章程”检查器集中显示目标、纪律、依据与职责分工；原始记录只保存名称、路径和哈希作为只读引用，不复制或改写原文。
- Agent 普通回复中的精确 `@别名` 会优先路由给被点名者，可形成 A→B→A 的因果对话链；人类直接输入 `@别名` 也会被识别。
- 普通 assistant 最终回复由 Session 事件自动回收到群聊；不要求 Agent 调用 `chat_send`。
- `(pass)` 表示本轮无新增内容；未继续 `@` 时不追加点名轮次。
- 每个 Agent 在一条链内默认最多发言 3 次，整条链最多 10 次自动回复，防止无限互聊。
- 新消息会令旧轮次过期；迟到回复不会污染新上下文。
- 运行中的协作轮可从顶栏立即停止；停止后迟到回复不会重新进入房间。协作运行时禁止改成员与顺序，避免中途换人造成路由歧义。
- UI 分别展示排队、已发送、已送达、思考中、已回复、跳过、失败和过期状态。
- “移出”只移除房间成员关系，不删除真实 DSH Session。
- 删除房间采用可恢复的软删除：房间进入侧栏“已删除”，消息、成员关系和真实 DSH Session 均保留。恢复时若名称已被占用，会生成清楚的“（恢复）”名称，而不是覆盖现有房间。
- 顶栏“台账”把任务、交接、决定、证据和分歧从聊天中抽成可追踪条目；支持负责人、期限、验收标准、状态和来源消息。每次变化追加历史并使用条目 revision 防止覆盖。
- 任务可选择停滞监控。计时状态随房间持久保存，到期只精确 `@`指定协调人；可推迟 10 分钟、标记受阻或完成，不会广播或自动改文件。
- 失败投递可只重试失败参与者，沿用原消息和因果链，不复制一条新的用户消息；旧失败尝试作为已被重试的历史保留。
- 人类消息可追加“纠正”。原文不会被改写，纠正会关联原消息，并只通知曾收到原消息的参与者。
- 服务端支持按正文、发言者和投递状态搜索完整房间记录；打开旧结果时进入稳定的历史片段模式，可明确返回最新消息。
- 参与者进入右侧检查器，不再长期占据消息区；已有会话通过独立搜索抽屉选择，最多显示 30 条结果。
- 房间栏压缩为低密度导航；正文保持约 760px 的可读宽度，Agent 使用稳定色彩头像和因果回复线，连续投递状态折叠为一条摘要。
- 侧栏入口使用与 DSH 一致的单色线性 SVG 图标，不再使用 Emoji；原生侧栏收窄时只保留图标，不会把“返回会话”逐字折行。
- @收件人、正文 @、输入内容、投递提示和发送按钮使用同一份最终收件人反馈；无收件人时明确显示“自动路由”或“仅记录”。
- Esc 只逐层关闭选择器、确认框、检查器或新建表单，不再退出群聊；返回 DSH 只走明确的返回控件。
- 草稿按房间保存并在返回后恢复；异步发送结果会校验房间 ID，不会把 A 房消息写进正在查看的 B 房。
- 消息中的 Markdown、代码和其他文本文件引用可在右侧检查器只读打开。插件区分 Artifact（逻辑文件）、Version（内容哈希版本）和 Replica（某会话工作目录中的副本）。
- 用户向上阅读历史时，新消息不会抢走滚动位置，而是显示“新消息”按钮。

## 权限边界

- 每个房间带有递增的策略版本；每条消息记录其提交时的策略版本与动作模式。
- “只读讨论/审计”由群聊额外拦截命令、文件修改和未知副作用工具；DOCX 抽取无需 shell，始终可用。
- “跟随 DSH”不修改原生配置，移除群聊额外拦截，由各会话当前原生沙箱和审批控制。
- “工作区内修改”将现有成员同步为 DSH 原生 `workspace-write / ask`；“完全权限”同步为 `danger-full-access / never` 并移除群聊额外拦截。这些真实 Session 的原生设置在离开群聊后仍保留；切回群聊只读只恢复群聊限制，不隐式重写原生会话设置。新增成员保留原生权限，可重新应用同步。系统权限约束仍有效。
- 变更必须由用户在权限界面明确执行；Agent、章程提案和台账决定不能改变房间策略。批量变更前检查所有成员是否空闲；不能在执行中途换权限。DSH 原生服务缺失、预设不匹配或成员使用无法通过公开 API 完整恢复的自定义预设时，给出具体错误，不虚报成功。
- 文件读取限定参与者工作目录或用户明确共享的单个绝对路径。文本上限 1 MB，DOCX 压缩文件上限 20 MB；按受限 ZIP/XML 解析，不运行宏、不跟随外部链接、不改原文件。正文、表格、脚注、尾注、评论、页眉页脚提供 XML 定位码，非页面排版/图像审查。

## 本地数据

房间状态保存在 `~/.dsh/dsh-chat-local/rooms.json`，目录权限为 `0700`、文件权限为 `0600`。当前状态版本为 v13，追加持久化草稿、多套阵容与创建凭据；整理批次保存在各对话中。旧章程、台账、消息、原生会话绑定和分享范围保留，不伪造过去的修订或验收记录。软删除不清除房间历史；读取到不支持的未来版本或无效顶层结构时停止加载，不以空状态覆盖原文件。旧版程序不能读取 v13；备份只保存升级时点，直接覆盖旧备份会丢失之后新增的数据，本版没有无损降级工具。

## 协作事项闭环

`chat_work` 提供 record / amend / acknowledge / progress / submit / review / comment 七种语义操作。除登记外都须带事项 id 与当前 revision；每次有操作 id、变更说明及 1–8 条本房间来源消息作为依据。来源可以是讨论消息，也可以是用户在台账中明确触发、带用户操作溯源的接手通知；普通系统公告不能充当用户授权。身份来自执行工具的 DSH Session，且只允许该房间有效群聊回合写入。

- 分派不是收悉：负责人只能由本人确认；无负责人任务可由成员认领。
- 交付不是验收：提交必须标明材料/结果版本，进入 `in_review`。若指定独立验收人，可由其确认或退回；未指定则等待用户。负责人不能自验收。
- 建议不是授权：Agent 登记决定初始为 `proposed`，不能自行变成 `decided`。分歧和证据可补充来源/说明，不能由 Agent 单方关闭。用户在台账中明确采纳、解决或验收；不产生文件执行权限。
- 更改任务范围或负责人会清除旧收悉/交付/验收并重新开放（用户明确登记阻断可保留受阻）；修改已采纳决定的内容会退回待决定，不沿用旧批准。归档不表示验收。“恢复显示”保留原完成/终止结果，未完成历史保持暂停；“重新开工”才清除旧认领、交付与验收，建立新的待处理周期，两者均不自动执行。历史版本恢复仍走原有重新开放规则。
- 普通 comment 只附注，不改变状态，不延后监控；实质 progress 则记录推进/阻断。重要交接变化在对话流留紧凑公告，完整内容按需打开台账。
- 幂等键相同且内容相同返回原操作结果；同键不同内容拒绝。同种类/同标题/同来源的再次登记明确指向现有事项，不静默吞掉差异。
- 新审计保留字段前后快照、来源快照与操作信息。每房间最多 1000 项台账，每项最多 1000 条历史事件，容量不足拒绝新增，不截断旧版本；提醒遇容量上限暂停并公告。

## 章程自更新协议

- `chat_memory`：房间成员读取现行章程、近期版本、提案、最近 24 条公开消息及台账。不会读取其他成员的私聊上下文。
- `chat_charter_propose`：只在当前房间的有效群聊回合中提交目标/章程修订。要求现行 `baseRevision`、理由、1–8 条真实讨论消息 ID，章程传完整新文本。可用 `replacesProposalId` 关联异议后的新稿。内容相同的重复调用幂等。
- `chat_charter_review`：执行 Session 只能代表自己确认或提出异议。所有现有成员明确确认后，写入新版本并在时间线公告；不能把沉默、模型普通表态或用户未作出的授权当作确认。
- 审阅与异议返修共用原有每人/总回复上限，不开启无限后台轮次。达到上限、未调用确认工具或未回应时保持待审；可在下一轮继续。
- 用户手动改章程会让基于旧版本的待审稿失效；新增/移除成员会让旧成员集的待审稿失效。恢复历史采用当前 revision 校验，避免覆盖同时发生的新修改。
- 自动修订不能改房间权限、模型、成员职责或原始记录文件。章程内容始终低于 Host 权限和用户明确要求；成员一致并不证明文本在事实或逻辑上正确。
- 每房间最多同时 3 项待审提案，最多保存 1000 项提案；到上限拒绝新增，不悄悄删除历史。版本和来源快照存于本机房间数据。

## 依赖与验证

- 需要 `dsh-bridge` 负责本机 Session 唤醒和消息投递。
- 不依赖远程服务或 `dsh-weave`。
- `npm run build` 将 `lib/text-protocol.js` 与 `lib/work-protocol.js` 的共享协议嵌入浏览器入口；修改协议后必须重新生成。前端与后端使用同一套待处理判断和接手阶段语义。
- `npm run check` 检查生成代码一致性、语法并执行群聊协议、HTTP 和 UI 逻辑回归测试。

## 导出与备份

房间设置中的导出按钮由本机服务写入 `~/.dsh/dsh-chat-local/exports/`，成功后显示可复制的绝对路径。每次生成唯一文件名，不覆盖旧备份；目录权限为 `0700`、文件为 `0600`。默认状态路径自定义时，导出位于同级 `exports/` 目录。页面必须收到写入成功确认才提示已保存，不依赖内嵌浏览器对 Blob 下载的支持。

JSON 保留房间全部字段及完整审计历史，包含快照 SHA-256；Markdown 用于阅读完整对话与当前台账，不替代 JSON 版本备份。不会另行读取私聊、密钥或引用文件；已经出现在群聊消息中的文本仍属于导出内容。备份在本机持久保留，不自动删除或上传。

## 已知边界

- 条件复查不是万能自动解障：旧记录的文件路径只能按明确引用识别；版本是否满足任务、外部系统状态和原生 DSH 自定义权限仍需负责人实测。Agent 声明解除阻断不是独立验收，交付仍走既有复核流程。新材料路径不会静默替换任务原先指定的材料/版本。
- 这是 DSH 0.1.5-rc.2 的本地插件，不是 DSH 的 fork。它使用 DSH 已有的原生单槽、Session、模型目录和工作目录能力；升级 DSH 后应重新运行测试和界面复核。
- DSH 0.1.5 起会随附新的会话格式；0.1.2 及更早由本插件经 `dsh-bridge` 写入的旧会话，其拼接消息的 `source.form` 不符合 v0→v1 迁移白名单，表现为唤醒成员时 `resume failed`。修复方式是把这些记录里的 `form` 改为 `relay`（新版 `dsh-bridge` 已改用该值），改动仅限该字段、原样保留其余字节与帧结构。affected 会话在 `~/.dsh/sessions` 下，处理前务必备份。
- 文件检查器提供文本预览及 DOCX 结构化阅读，不包含 DSH 编辑器的完整语法高亮、diff、Word 原版分页或图片/PDF 渲染。自动编号、复杂公式、嵌入对象、完整样式继承及修订版式不能完整复现；限制提示保留，模型不能据文本抽取宣称完整视觉审查。
- 房间事件仍保存在单机 JSON 状态中，不是多设备实时协作文档。
- 消息不再按条数静默删除，但 JSON 状态仍整体读取和写入；超大房间需要后续分页索引/存储升级，不能据此宣称无限容量。导出不会自动上传，JSON 导入/还原界面尚未提供。
- Markdown 是受限子集，支持标题、列表、表格、代码、引用与安全链接；不执行 HTML，不自动加载外部图片，不包含数学公式、复杂嵌套或完整 CommonMark 兼容性。
- 未开始的新对话/新群组草稿保存在服务端，并以 localStorage 保存未同步输入与操作编号；页面标示同步失败或版本冲突。清理浏览器存储仍可能丢失尚未同步的文字。已开始对话的普通输入草稿及未确认发送编号仍使用标签页 sessionStorage，关闭标签页可能丢失，不能与新草稿箱混淆。
- 停滞监控只对用户明确开启监控的台账任务生效；普通聊天静默不会触发协调人。当前按分钟配置，不包含工作日历、免打扰时段或跨设备通知。
- 外部历史记录只作为带 SHA-256 的只读来源引用；不会自动把原群聊和 Bot 私信导入新的活动时间线。
- 自动修改全局成员职责、跨房间共享记忆和私信侧信道尚未开放。执行权限由用户在独立权限设置中选择，具体任务仍受用户授权范围约束；开启能力不等于指令任意改动文件。
